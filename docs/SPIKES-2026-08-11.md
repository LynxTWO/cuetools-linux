# SLICE-001 M1 spike results (2026-08-11)

All three M1 spikes from SLICE-001-verify.md ran on the target-class machine
(Ubuntu 24.04.4 LTS, .NET SDK 10.0.110, PowerShell 7.6.4, clang 18). All
three passed. Evidence below; plain claim first, then the receipt.

## S-1 PASS: the fork engine builds and runs on Linux (closes Q-003 / U-005)

**Vendor staging works under PowerShell Core on Linux.** Receipt:
`pwsh -NoProfile -File eng/ci/Prepare-VendorSources.ps1` in the fork clone
exited 0 and reported "Prepared vendor source stage: 1556 files,
98F46C694EB3128475F3D87CD27662DB1DB68E80570A613959341E5E97F46E36".

**The engine compiles clean.** Receipt: `dotnet build
CUETools.Processor.csproj -f netstandard2.0 -c Release` completed with
0 warnings, 0 errors in 12.46 s, building the full dependency chain
(Codecs, CDImage, AccurateRip, Parity, Compression, CTDB, Ripper, Freedb,
staged TaglibSharp).

**SDK resolution finding:** the fork's global.json pins SDK 8.0.422 with
rollForward latestFeature, so dotnet commands run from inside the fork tree
fail on a machine with only SDK 10. Builds invoked from a working directory
whose own global.json permits SDK 10 (the cuetools-linux repo pattern per
D-014) resolve and build correctly. This is the documented build approach.

**The engine executes, not just compiles.** Receipt: a net10.0 harness with
ProjectReferences into the fork ran: WAV encode/decode roundtrip of 88,200
samples byte-identical; `CDImageLayout.FromString` -> 3 tracks, TOCID
computed; `AccurateRipVerify.CalculateAccurateRipId` -> 0001d718-0006205c-
1c032003. Harness printed SPIKE PASS, exit 0.

**Test-project finding:** CUETools.TestParity, TestCodecs, and TestProcessor
target net47 only and cannot run on the Linux runtime. The M2 fork PR
should add a modern test TFM (owner approval per the D-028 stop list).

## S-2 PASS: DeviceId behaves safely on Linux (closes Q-002 / U-006)

On the netstandard/net10 path, `CUEToolsDB.GetUUID()` builds the CTDB
fingerprint from the machine name only (`DeviceIdBuilder().AddMachineName()`
hashed SHA-256, base64url); the processor-id and motherboard-serial
collectors are NET47-gated (`CUEToolsDB.cs:315-322`). Receipt: the S-1
harness produced a stable 43-character value across calls in one process.
Privacy note for EDD section 8: on Linux the fingerprint is a hashed
hostname, nothing more.

## S-3 PASS: Avalonia 12.1 NativeAOT publish on linux-x64 (verifies A-002 toolchain)

A minimal Avalonia 12.1.1 app (Fluent theme, compiled bindings default) on
net10.0 published with `PublishAot=true; StripSymbols=true;
InvariantGlobalization=true` for linux-x64.

| Measure | Value |
| --- | --- |
| Native binary | 18,859,576 bytes (18.0 MB) |
| libSkiaSharp.so | 11.2 MB |
| libHarfBuzzSharp.so | 2.8 MB |
| Shipping payload total | ~32.8 MB installed |
| Main binary gzipped | 7.7 MB |
| Process start -> window open | 425 / 440 / 457 ms (3 runs, Xvfb) |

The separated `AotSpike.dbg` (42.9 MB) is debug symbols and never ships.
Against D-025: installed budget 60 MB leaves ~27 MB headroom for the real
app; startup budget 2 s has ~4x headroom.

**Refined residual risk (A-002b, Watching):** this proves the UI toolchain,
not the whole app under AOT. CUETools.Processor depends on Newtonsoft.Json,
which is reflection-heavy and a known AOT hazard. Test engine-under-AOT as
soon as the app skeleton references it; the named fallback remains trimmed
self-contained publish (D-030).
